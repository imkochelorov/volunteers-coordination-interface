# Проверка результата

Команды: `npm run check` и `npm test`. На момент проверки прошли **36 тестов**: 23 доменных, 6 интеграционных сценариев обработчика HTTP и 7 сценариев адаптера Telegram. Число тестов может увеличиваться; актуальный результат выводит `npm test`.

Домен проверяется на настоящей SQLite, включая одновременные операции двух потоков и повторное открытие файла. HTTP-тесты вызывают настоящий обработчик `server.js` через потоки запросов и захват ответа в памяти: работают парсинг JSON, сессии, cookies, CSRF, маршруты и транзакции. Они не открывают TCP-порт. Telegram-тесты используют рабочий адаптер Bot API и подменяют только сетевой транспорт; настоящие серверы Telegram не вызываются.

Дополнительно проверены независимые статусы нескольких холлов одной публикации, выбор всех холлов с Hall 5, личные теги разных менеджеров, смена пула, роли с совмещением, одноразовые ссылки Telegram, устаревшие поколения назначений, неадресованные вопросы без общей рассылки, сохранность переименованных тегов, защита последнего администратора, CSRF, источник запросов, недоступность веба чистому волонтёру, отсутствие паролей в ответах, ключи повторных HTTP-запросов и отзыв приглашения при смене пула без хранения секрета в открытом виде.

## Что не проверено в этой среде

- Прослушивание TCP-порта: `listen` на `127.0.0.1` вернул `EPERM`. Поэтому запуск HTTP-сервера и открытие интерфейса из браузера здесь не подтверждены. Автоматические тесты обработчика не заменяют такую проверку.
- Визуальный вид и работа интерфейса в настоящем браузере, включая телефон: доступной браузерной сессии не было.
- Живой Telegram: токен нового бота не предоставлен. Реальные `/start`, получение сообщений и доставка после блокировки бота требуют проверки с собственным тестовым аккаунтом.
- Docker Compose: контейнерный запуск здесь не выполнен.
- Исходники старого бота: доступ к GitHub заблокирован; разбор конкретных файлов не завершён. См. [статус исследования](legacy-review.md).
- Отправка в целевой GitHub-репозиторий: сетевая ошибка DNS и недействительная локальная авторизация `gh`; публикация не подтверждена.

## Проверка на сервере мероприятия

1. Настройте `.env`, запустите `npm start` и откройте страницу. Создайте менеджеров разных холлов и двух тестовых волонтёров.
2. Подключите волонтёров настоящими личными ссылками и назначьте им одну групповую задачу. Проверьте цикл принятия и завершения, обновление второго сообщения и бездействие старой кнопки.
3. Задайте вопрос в боте, передайте его TC и холлу, ответьте от адресата и подтвердите решение менеджером. До подтверждения блокировка должна сохраняться.
4. Отключите работу с чужими холлами, проверьте отказ действий; включите и повторите.
5. Заблокируйте бота тестовым волонтёром, создайте назначение, проверьте ошибку доставки. Разблокируйте, нажмите `/start` и выполните повторную отправку.
6. Перезапустите приложение и проверьте задачи, назначения, обсуждения и историю. Выполните резервное копирование по инструкции README.
