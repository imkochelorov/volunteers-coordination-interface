# Технический разбор прежнего Telegram-бота

Исследован публичный [Shemplo/volunteers-coordination-bot](https://github.com/Shemplo/volunteers-coordination-bot) в ревизии [`9f9fdb2c371ac9c46649f00a136b252c9f94cf32`](https://github.com/Shemplo/volunteers-coordination-bot/commit/9f9fdb2c371ac9c46649f00a136b252c9f94cf32), ветка `master`, состояние на 15 ноября 2026 года. При первоначальной разработке доступ был заблокирован; во время аудита исходники прочитаны через GitHub. Старый репозиторий не изменялся и не запускался.

## Рассылка, авторизация и ограничения

Рассылка идёт в личные чаты участников подписанной группы и связанные групповые чаты/темы. Сохраняется ID отправленного сообщения; обновление задачи редактирует соответствующую копию. Последняя исследованная ревизия уменьшает спам: отдельное уведомление об изменении/отмене посылается только в личный чат, а упоминание автора регулируется конфигурацией. Это полезный практический сценарий: состояние надо синхронизировать во всех копиях задания и не считать автора обязательным адресатом каждого уведомления. Источники: [ChatsBroadcaster.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/bot/chat/service/ChatsBroadcaster.java), [TaskContext.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/bot/chat/task/TaskContext.java), [example-configuration.yml](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/example-configuration.yml).

Очередь `ChatsBroadcaster.tasksQueue` находится в памяти. Исключение Telegram после извлечения задания записывается в лог без возврата задания в очередь. В прочитанной схеме нет постоянного outbox или записей дедупликации Telegram update ID; `TelegramBot.consume` маршрутизирует событие без такой проверки. Обёртки SQL записывают ошибку в лог и для запросов чтения возвращают `null`. Эти механизмы не дают требуемых новой системе наблюдаемой ошибки доставки, устойчивого повтора и атомарности бизнес-действия с уведомлением. Источники: [ChatsBroadcaster.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/bot/chat/service/ChatsBroadcaster.java), [TelegramBot.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/bot/TelegramBot.java), [DatabaseService.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/db/DatabaseService.java).

Авторизация прежнего бота выполняется командой `/authenticate`: введённый код сравнивается с общим кодом роли из YAML и назначает соответствующую роль. README прямо указывает хранение этих кодов открытым текстом. Это не персональное одноразовое приглашение к учётной записи волонтёра; новая система использует собственные пароли веб-пользователей и одноразовые токены привязки Telegram. Источники: [UserChatContext.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/bot/chat/UserChatContext.java), [CodeAuthenticationPending.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/main/java/ru/itmo/nerc/vcb/bot/chat/pending/CodeAuthenticationPending.java), [README.md](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/README.md).

## Проверки и развёртывание

В исследованном дереве два класса параметризованных тестов: [TestTaskUtils.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/test/java/ru/itmo/nerc/vcb/bot/chat/task/TestTaskUtils.java) проверяет выбор/исключение групп и повторы; [TestInlineQueryGrammar.java](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/src/test/java/ru/itmo/nerc/vcb/bot/chat/antlr/TestInlineQueryGrammar.java) — разбор inline-команд. Тестов полного сетевого обмена, конкурентных назначений, постоянной очереди доставки и перезапуска в этом дереве не обнаружено. Сборка старого проекта в рамках этого чтения не запускалась.

[GitHub workflow](https://github.com/Shemplo/volunteers-coordination-bot/blob/9f9fdb2c371ac9c46649f00a136b252c9f94cf32/.github/workflows/deploy-testing.yml) выполняет Maven-сборку на JDK 21, но шаг deploy содержит только `echo "To be done"`. Рабочее развёртывание из этого workflow не следует; README описывает ручной запуск JAR на хосте.

Новая система остаётся самостоятельным приложением: не использует Java-классы, код, протокол, БД или работающий экземпляр прежнего бота. Выявленные сценарии оценены как справочный материал; совместимость и перенос прежних данных в объём аудита не добавлены.
